# Shared core spec

**Status:** accepted (2026-11-22). C0 passed (#246, PR #258). C5 done (#251,
PR #261; releases `core-v0.1.0`, `core-v0.2.0`). C4 in progress (#250): the
Apple apps call the core for fade (#270) and the conversation projection,
predicates and Agent stage (#275), and recurrence and timed reminders. The
watch compiles no rule code (`TasksWatchWire.swift` only). C1–C3 open.

**Rests on:** ADR 0025 (shared Rust core), ADR 0015 (shared registries),
ADR 0013 (Windows on the Android code), ADR 0002 (own backend).

## 1. Goal

One implementation of the task rules and the sync decisions, used by every
client: iOS, macOS, web, Android and Windows. The hosts stay native. The core
does no I/O.

## 3. What the core holds

The core receives values and returns values. The host supplies the time
(`now` as an ISO-8601 instant, `today` as `YYYY-MM-DD`) and the UTC offset
where a date-only value needs one.

| Module | Functions | Vectors |
|---|---|---|
| `fade` | `row_opacity`, `should_fade`, `fade_fill` | `task-fade.json` |
| `views` | `task_view_membership` | `task-views.json` |
| `recurrence` | `next_scheduled_date`, `occurrence_id` | `recurrence.json` |
| `reminders` | `shift_reminder_for_recurrence`, `shift_reminder_on_reschedule`, `should_arm_reminder` | `reminders.json` |
| `convo` | `derive_conversation` | `convo-derived.json` |
| `sync` | `check_pull_page`, `plan_pull_row`, `plan_push_response`, `server_rejection_reason` | `sync-engine.json` |
| `conformance` | `run_conformance(fixture, json)` runs one vector file inside the core | all |

### 3.1 Sync decisions

The host owns the store and the transport. The core decides.

- **`check_pull_page(cursor, page, resets_so_far)`** returns `apply`,
  `apply_and_continue`, `reset` or `fail`. A reset is allowed once per sync.
  A cursor that moves back fails. A page that says "more" without progress
  fails.
- **`plan_pull_row(entity, row, current, pending_fields, pending_delete)`**
  returns one plan for one pulled row:
  - `turn`: store the turn under its task id and sequence.
  - `skip`: a setting tombstone; keep the local setting.
  - `tombstone`: reject queued ops for the row. A task keeps its local
    fields with `deletedAt` set; other entities are deleted.
  - `shadow_only`: a local delete is queued; record the server snapshot only.
  - `merge`: the merged fields. A field with a queued local op keeps its
    local value ("local wins until its push lands").
- **`plan_push_response(sent_ids, outcome)`** returns `apply_results`,
  `reject_one`, `bisect` or `fail`. A 400 on a batch splits it in half. A
  400 on one op rejects that op with the server's reason. A response whose
  ids differ from the sent ids fails.
- **`server_rejection_reason(status, body)`** turns a 400 body into the text
  the Not synced list shows.

Row fields cross the boundary as JSON object strings. Typed records carry
everything else.

## 4. What stays native

UI and navigation, the undo stack, the store engine (SwiftData, SQLDelight,
IndexedDB), HTTP and WebSocket transport, sign-in, keychain and DPAPI,
notifications, EventKit, Things import, `DateParser`'s natural-language
parsing, the watch.

## 5. Build and CI

- `.github/workflows/core.yml` is the build gate. It runs on pull requests,
  on `main` and on `wt/**` pushes that touch `core/`, `registry/` or the
  generator.
- Jobs: `core-rust` (generator check, `cargo test` with all vectors,
  licences), `core-apple` (iOS, iOS simulator and macOS slices, XCFramework,
  Swift harness on macOS), `core-android` (three Android ABIs, size only),
  `core-jvm` (Linux and Windows, Kotlin harness through JNA), `core-wasm`
  (WASM package, Node harness, Brotli size).
- Each job writes its numbers to the job summary and fails over budget.
- **Releases (C5, #251):** a tag `core-vX.Y.Z` runs
  `.github/workflows/core-release.yml`, which builds every artifact through
  `core.yml` and publishes them as GitHub release assets with a
  `release.json` manifest. `scripts/core-pin.sh X.Y.Z` pins a release in
  `core/release/` (the manifest and a Swift package with a URL and checksum
  `binaryTarget`). Apps link the pinned release, never a local build. Steps:
  `core/release/README.md`.
- **Agents do not install Rust.** `core-rust` fails on a clippy warning or a rustfmt diff (it uploads the formatted sources as `core-rustfmt`). When `Cargo.lock` is missing or stale,
  `core-rust` uploads the new lockfile as the `core-lockfiles` artifact and
  fails. Download it with `gh run download`, commit it, push again.

## 6. Budgets (C0 gates, from Bipe ADR 0267)

| Gate | Budget |
|---|---|
| Conformance | Every vector passes in each packaged artifact |
| Native slice | ≤ 1 MiB stripped |
| WASM | ≤ 300 KiB Brotli |
| Time per call | p95 ≤ 5 ms |

## 8. Open questions

| Question | Default |
|---|---|
| Time zone for a date-only `created` in fade | The host passes its UTC offset in seconds *(default)* |
| Watch recurrence | The phone runs the core for a wrist completion; the watch compiles no `DateParser` (settled in C4) |
| List membership on Apple | Moves to the core only after mz checks list scrolling on a device with the core calls already in place (#250) *(default)* |
| Single-field conversation reads | `isTerminal`, `isClaimed`, `needsHumanReview` stay in Swift: one field each, a core call would only add cost *(default)* |
| Android packaging | Releases ship `jniLibs` + Kotlin bindings, not an AAR; C1 packages them in the `android/` Gradle build *(default)* |
| Apple link form | SwiftPM `binaryTarget` from a release (C5); CI-built until then *(default)* |
| Windows architectures | x64 first; arm64 after W1 *(default)* |
